# Glossary — Ubiquitous Language

> **Reader:** All. **Mode:** Reference.
> One term, one definition, used consistently across the whole handbook. If a doc uses a word from
> the domain, it means what it says here. Missing a term? Add it, don't redefine it inline.

## Core

**Plugin** — a standalone compiled binary, dispatched as a subprocess by the `metaphor` CLI.
`metaphor-codegen` is the code-generation plugin. See [ADR-0001](adr/0001-subprocess-plugin-dispatch.md).

**`metaphor-codegen`** — the binary this repo builds. Provides the `make`, `module`, `apps`,
`proto`, `migration`, `seed`, and `routes` command groups. Library name: `metaphor_codegen`.

**Scaffolding** — generating conventional, near-empty structure (files, layers, contracts) that a
developer then fills with behavior. This plugin's whole job. Contrast with business logic, which it
never generates.

**Generation / regeneration** — producing code from a source of truth (schema, template, or
skeleton). *Re*generation is running it again over existing code; it must preserve `// <<< CUSTOM`
regions.

**`// <<< CUSTOM` marker** — the convention delimiting developer-owned code inside an otherwise
generated file. Everything between `// <<< CUSTOM` and `// >>> CUSTOM` survives regeneration;
everything outside is the generator's to overwrite. The contract that makes regeneration safe.

**Source of truth (SSoT)** — the one artifact a derived thing is generated from. For entities, the
schema YAML. For module structure, the `backbone-module` skeleton repo. Hand-editing a derived
artifact instead of its SSoT is the anti-pattern the framework is built to prevent.

## Domain-Driven Design

**Bounded context** — a self-contained business domain with a clear boundary, implemented as a
**module**. Owns its full vertical slice (domain → persistence → HTTP) and communicates with
others only through explicit contracts (proto), never shared internal types.

**Module** — the code artifact for one bounded context: a Rust crate with the DDD 4-layer layout.
Created by `module create` (which clones the `backbone-module` skeleton). Registered in the
workspace `metaphor.yaml`.

**Skeleton** — the canonical starting-point repo (`backbone-module`) that `module create` clones.
The single source of truth for module structure; to change the module layout, edit the skeleton,
not this plugin. See [ADR-0002](adr/0002-skeleton-clone-scaffolding.md).

**Entity** — a domain object with a unique identity and a lifecycle, tracked by ID (`User`,
`Payment`). Defined schema-first (not `make entity`, which is deprecated). Contrast **value object**.

**Value object** — a domain object defined entirely by its attributes, immutable, freely
replaceable (`Email`, `Money`, `Address`). Generated by `make value-object` (emits `.proto` + `.rs`).

**Aggregate / aggregate root** — a cluster of entities and value objects treated as one consistency
boundary, accessed through a single root entity. Has dedicated templates under
`src/templates/aggregate/`.

**Domain event** — a record that something *happened*, named in past tense (`UserCreated`,
`PaymentProcessed`). Generated by `make event` as `.proto` + `.rs`.

**Specification** — a business rule expressed as a composable predicate (`UserIsActive`,
`OrderCanBeCancelled`), combinable with AND/OR. Generated by `make spec`.

**Repository** — the data-access abstraction. A **trait** in the domain layer defines the
interface; an **implementation** in the infrastructure layer provides concrete database logic, so
backends swap without touching domain code. Generated by `make repository`.

**Domain service** — cross-entity domain logic that doesn't belong to any single entity. Generated
by `make service`.

## Clean Architecture layers

**Domain layer** (`src/domain/`) — pure business logic, no external dependencies. Entities, value
objects, events, repository *traits*, domain services, specifications.

**Application layer** (`src/application/`) — orchestrates the domain to fulfill use cases;
implements CQRS. Commands and queries.

**Infrastructure layer** (`src/infrastructure/`) — concrete implementations of domain interfaces:
database repositories, cache, messaging, projections.

**Presentation layer** (`src/presentation/`) — external communication: HTTP handlers, gRPC
services, CLI.

**Dependency rule** — dependencies point inward. Outer layers depend on inner layers; the domain
layer depends on nothing external. Never the reverse.

## CQRS

**CQRS** — Command Query Responsibility Segregation: reads and writes are separated into distinct
types.

**Command** — an intention to *change* state, named as an imperative verb (`CreateUser`,
`UpdatePayment`). Write side. Generated by `make command` into `src/application/commands/`.

**Query** — a request to *read* state with no side effects, named as a retrieval verb (`GetUser`,
`ListPayments`). Read side. Generated by `make query` into `src/application/queries/`.

## Contracts & data

**Proto-first** — cross-module and cross-service contracts are defined in Protocol Buffers before
implementation, giving backward-compatible, language-neutral interfaces. Handled via `tonic-build`
and the `proto` command group.

**Schema-first** — entities are described once in `schema/models/*.model.yaml`; domain types,
proto, and migrations are generated from that description. Owned by the `metaphor-plugin-schema`
plugin (`metaphor schema generate`), not this one. See [ADR-0003](adr/0003-schema-first-over-make-entity.md).

**Migration** — a versioned SQL change to the database schema. Generated and run via the
`migration` command group (which shells out to `sqlx` to apply them).

**Seeder / seed** — code or SQL that inserts baseline or test data. Managed by the `seed` command
group and `migration seed`.

## Tooling terms

**`TemplateContext`** — the struct (in `template_processor.rs`) carrying the values —
module/entity/aggregate names in their case variants — used to fill `{{PLACEHOLDER}}` tokens in
`make` templates.

**Placeholder** — a `{{TOKEN}}` marker in a template file (or filename) replaced during generation
(`{{MODULE_NAME}}`, `{{ENTITY_NAME_SNAKE}}`, …). Bare `metaphor`/`Metaphor` is intentionally *not*
a placeholder anymore.

**`metaphor.yaml`** — the workspace manifest listing every project and its type. A generated module
must be registered here to be discovered by the `metaphor` CLI.
